# 手動測定と集計の現状設計

2026-10-30。READMEの手動実行・通信量の説明を引き継ぎ、2本のスクリプトの入出力と集計条件を補う。

## 目的と境界
- 回線とWi-Fiの指標を1回ずつ測定し、同じ端末に蓄積したCSVから時間帯ごとの平均を確認する。
- 定期実行、リモート管理、測定履歴の外部送信、故障箇所の自動断定は実装されていない。
- macOSの`system_profiler`、`curl`、`ping/ping6`、`awk`等を使う。測定コマンドは実通信を行うため、文書確認で実行しない。

## 処理と入出力
| 実装 | 入力 | 出力 |
| --- | --- | --- |
| [measure.sh](../measure.sh) | 手動起動、任意の`ROUTER_HOST` | `log/measurements.csv`への1行追記とその行の標準出力 |
| [report.sh](../report.sh) | 同じCSV | 件数/期間、3時間ごとの平均、下りv4の並べ替えによる行表示 |

- `measure.sh`は自分の配置場所を基準に`log`を作り、CSVが無ければヘッダーを作る。
- Cloudflareの測定先へIPv4/IPv6それぞれ10000000バイトの下り取得を行い、0で埋めた約10MiBの一時ファイルをIPv4で送信する。
- `curl`の各呼出しの上限は45秒。速度のバイト/秒を8倍し、1000000で割ったMbpsを小数1桁で記録する。
- IPv4/IPv6の既定宛先へ5回ずつpingする。ルーターへのpingは`ROUTER_HOST`を指定したときだけ行う。
- Wi-Fi情報からRSSI・送信レート・チャンネルを抜き出す。チャンネル内のカンマはセミコロンへ置換する。

## CSVの契約
| 列 | 内容 |
| --- | --- |
| `timestamp` | 端末のローカル時刻、`YYYY-MM-DD HH:MM`。タイムゾーン列はない |
| `dl_v4_mbps, ul_v4_mbps, dl_v6_mbps` | 下りv4・上りv4・下りv6。上りv6の測定列はない |
| `ping_v4_ms, ping_v6_ms, ping_router_ms` | pingの平均値。未指定/取得できない項目は空欄になり得る |
| `rssi_dbm, tx_rate_mbps, channel` | 端末上で得たWi-Fi指標。SSID/BSSIDの列はない |

- CSVは端末の時刻と通信品質を含む。送信試験のpayloadは0詰めファイルであり、このCSVではない。
- 取得エラーの専用状態列はない。空欄や0を、測定成功や故障の確定値として扱わない。

## 集計の規則と限界
- `report.sh`はCSVが無ければ終了コード1。ヘッダーを除いた行数、最初/最後の記録時刻を表示する。
- 時刻の時部分から`floor(時/3)*3`の区間へ分け、下りv4・上りv4・下りv6・遅延v4・RSSIを単純平均する。
- 時刻が空でない行を件数に含める。各指標の欠測を除外せず、awkの数値化で空欄が0として計算され得る。
- 最良/最悪表示は下りv4で昇順にし、`head`/`tail`のパイプで行を取り出す。少数行を含め両端の表示を確認する必要がある。

## 変更時の確認条件
- 合成CSVだけで未作成・ヘッダーのみ・1行・複数時間帯・空欄・同値を確認し、3時間区間と各平均の分母を確かめる。
- 最良/最悪の行が同じ1行の場合と、複数行の両端を区別して確認する。
- `measure.sh`の検証は通信量・測定先の条件を確認した明示的な手動実行とする。実測値やWi-Fi情報をテスト資料に転記しない。
